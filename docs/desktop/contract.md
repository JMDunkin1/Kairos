# Kairos desktop contract

The authoritative source is this repository. The single installed application is `/Applications/Kairos.app`; `npm run app:install` rebuilds it here and replaces the former `/Applications/QORE.app` when present. `config/qore-desktop.json` is an expandable registry of strategy identities, current stages and operating instructions. There is no fixed catalogue or portfolio sleeve count. Add reviewed definitions and isolated evidence/runtime adapters as the symphony grows; registration never authorizes trading. The leverage comparison baseline and natural-gas seasonal components remain supporting evidence and implementation, respectively. The existing bundle identifier, preference keys, runtime paths and QORE protocol identifiers remain stable across the rename.

The desktop serves `desktop.html`. Its isolated `/ngas.html` entry serves the original two NGAS routes, Account (`command`) and Backtests (`backtest`). Actual account values come only from the existing sanitized M1 telemetry adapter. The app starts that connection lazily when an account endpoint is requested and stops its owned bridge on quit. No order submission or reconciliation endpoint exists. The deployed NGAS engine, training splits, costs, forecasts, broker gates and live authorization are unchanged.

Leverage and the three newer candidates read only the approved exports in `assets/released-replay/` and `assets/offline-paper/`. Their original manifests, audit closure, cost scenarios, failed screens, prospective windows and input blockers are preserved byte-for-byte. The baseline is available only as a leverage comparison. Historical playback supplies no new validation or actual account returns.

The canonical experiment ledger stays in `research/experiment-log/`. The hub reader opens it in place, preserves revisions, inheritance, partial appends and failure/retry records, and exposes sanitized browser DTOs. The desktop never rewrites it. Research owners may continue appending while the app is open.

Synthetic trend, reversion and spread examples are internal accounting test fixtures, not portfolio products. The pure simulator requires explicit adapters. Fixtures, simulator code, synthetic run stores and demo report screens are excluded from the application bundle. Existing native user data is not deleted by app installation or cleanup.

`docs/desktop/provenance/retained-documents.json` binds original instructions, handoffs, manifests and review receipts relocated from obsolete development folders. Those documents retain their historical bytes and paths. Superseded executable source is available in Git history; it is not retained as another checkout or archive. `cleanup-manifest.json` records deletion decisions and the evidence kept for retired research.

Run `npm run lint`, `npm run build`, `npm test`, and native launch/quit checks before delivery. Desktop regressions cover registry expansion, origin and host enforcement, read-only proxying, owned-child shutdown, absence of synthetic/order endpoints, ledger preservation, tamper refusal and replay accounting. Broad changes require fresh independent review. Installation retains a signed `release-manifest.json` with packaged file hashes; temporary build caches and the replaced app are deleted.
